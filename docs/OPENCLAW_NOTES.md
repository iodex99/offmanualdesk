## 2. Install on Windows (native)
- Runtime requirements (Node version, etc.):
  - `package.json` `engines.node`: `>=24.16.0 <25 || >=26.1.0` (npm metadata for 2026.11.6; `docs:install/node-compatibility`). Node 22, 23 and 25 are refused. Node 26 is "recommended", Node 24 is "supported (CI runtime)". 24.22.1+ / 26.12.1+ are "strongly recommended" (eMudhra key rejection); `docs:plugins/building-plugins` lists 24.22.1+/26.12.1+ as the plugin-dev requirement. **Use Node 24.22.1+ or 26.12.1+.**
  - Startup also probes the loaded `node:sqlite` (WAL-safe SQLite 3.51.3+/3.50.7+/3.44.6+, NUL-safe TEXT decoding); a supported version number with a failing probe is refused (`docs:install/node-compatibility` "How the gate decides"; `openclaw.mjs` `ensureSupportedRuntimeVersion`). Official Windows Node zips are expected to pass — **UNVERIFIED on Server 2022 (lab L1)**.
  - Windows exec prefers PowerShell 7 (`pwsh`) and falls back to Windows PowerShell 5.1; Store app-execution aliases are skipped (`docs:platforms/windows`). Git for Windows is only needed for "New workspace"/worktree features.
  - Managed startup (`openclaw gateway install`) registers a Scheduled Task with the user's **S4U** principal: "S4U does not provide Windows network credentials or access to encrypted files; installations that need those capabilities can retain an operator-configured Password task" (`docs:platforms/windows`). Relevant to logged-off gateways (ARCHITECTURE F4.6, L5): an S4U-started gateway cannot reach `\\fileserver\share`.
- Install layout we can relocate to `C:\Program Files\OffManual\versions\<v>\openclaw`:
  - npm package name: **`openclaw`**; `bin`: `{ "openclaw": "openclaw.mjs" }`; `type: module`; `main: dist/index.js` (npm registry metadata, 2026.11.6). **Entry point script: `<package root>\openclaw.mjs`**, i.e. for `npm install --prefix <dir>` it is `<dir>\node_modules\openclaw\openclaw.mjs`.
  - The supported embedding pattern is exactly "real `node_modules` installation + spawn `<hostNode> <pkg>\openclaw.mjs gateway …`" (`docs:gateway/embedding`, "Start the child with an embedding preset"). "Install; do not flatten": do not copy only `dist/` or vendor extension files; bundled extensions use bare `openclaw/plugin-sdk/*` self-imports that need normal Node resolution (`docs:gateway/embedding`).
  - Runtime never writes into the package directory: "Runtime loading never runs a package manager, repairs a dependency tree, or mutates the OpenClaw package directory" (`docs:plugins/dependency-resolution`). So a read-only `Program Files` install is consistent with docs — **lab L1 must confirm** (e.g. compile cache goes to `%TEMP%\node-compile-cache\openclaw`, `docs:help/environment` "Temporary compile cache"; paths >200 chars are skipped on Windows).
  - Install scripts: `preinstall: node scripts/preinstall-package-manager-warning.mjs`, `postinstall: node scripts/postinstall-bundled-plugins.mjs` (npm metadata). The postinstall prunes stale `dist` files using `dist/postinstall-inventory.json` and restores the `@openclaw/fs-safe` native prebuild (`scripts/postinstall-bundled-plugins.mjs`, `scripts/lib/fs-safe-prebuild.mjs`); it can be skipped with `OPENCLAW_DISABLE_BUNDLED_PLUGIN_POSTINSTALL`, but then the fs-safe prebuild restore is also skipped — **do not skip; run the install on a Windows x64 build runner** so native optional deps (`@esbuild/win32-x64`, `sqlite-vec-windows-x64`) resolve. Package size: 308,745,740 bytes unpacked, 20,293 files.
  - Several official plugins are **not** in the core package and are separate npm packages at the same version: e.g. `lobster`, `diagnostics-otel`, `memory-lancedb`, `duckduckgo`, `brave`, `discord`, `slack`, `whatsapp` (root `package.json` `files` excludes `dist/extensions/<id>/**` for these). Telegram, memory-core, browser, anthropic, openai **are** bundled.
  - No Windows standalone/fat-binary build: "Windows standalone builds are not supported" (`docs:install/standalone`).
  - Process tree: `openclaw.mjs` may respawn itself (compile-cache/NODE_OPTIONS respawn, `src/entry.respawn.ts`; `node-runtime-recovery.mjs`). "A foreground Gateway does not follow the lifetime of the process that started it" (`docs:cli/gateway/running`). Desk must put the child in a **Job Object with KILL_ON_JOB_CLOSE** and set `OPENCLAW_NO_RESPAWN=1` (embedding preset: "prevents OpenClaw from handing an update restart to a detached child", `docs:gateway/embedding`).
- How to set the state directory per user:
  - Env **`OPENCLAW_STATE_DIR`** (mutable state dir; default `~/.openclaw`), **`OPENCLAW_CONFIG_PATH`** (config file; default `$OPENCLAW_STATE_DIR/openclaw.json`) — `src/config/paths.ts` (`CONFIG_FILENAME = "openclaw.json"`, comment "Default: ~/.openclaw/openclaw.json (or $OPENCLAW_STATE_DIR/openclaw.json)"), `docs:help/environment`.

## 3. Gateway
- Config file location and format:
  - **JSON5** at `$OPENCLAW_CONFIG_PATH` (default `~/.openclaw/openclaw.json`); "If the file is missing, OpenClaw uses safe defaults"; must be a regular file; OpenClaw writes replace it atomically, so no symlinked config (`docs:gateway/configuration`). `${VAR}` substitution (uppercase names only), `$include`, SecretRefs `{ source: "env"|"file"|"exec"|"store", provider, id }` (`docs:gateway/configuration/environment-variables`).
  - Startup refuses unless `gateway.mode: "local"` is set (or `--allow-unconfigured`) (`docs:cli/gateway/running`). Invalid config / required offline migration → exit code **78**; read failures → exit 1 (`docs:cli/gateway/running`, `docs:gateway/embedding`).
  - Startup auto-applies prompt-free legacy-key migrations to single-file configs, except configs using `$include`, Nix-managed configs, and configs from a newer version (`docs:cli/gateway/running`).
  - With `OPENCLAW_CONFIG_READONLY=1`, all OpenClaw config writes are blocked; doctor prints config repairs as a redacted merge patch instead (`docs:cli/config`).
- Bind address and port settings:
  - `gateway.port` (default 18789; precedence `--port` > `OPENCLAW_GATEWAY_PORT` > `gateway.port`), one port multiplexes WS + HTTP. `gateway.bind`: `loopback` (default on regular hosts) | `lan` | `tailnet` | `auto` | `custom` — use mode names, not `127.0.0.1` (`docs:gateway/config-gateway`).
  - **Derived ports** (`docs:gateway/multiple-gateways`): base+1 = MCP-Apps sandbox listener (only when `mcp.apps.enabled`, opt-in, `docs:cli/mcp/apps`); base+2 = browser control service (bundled `browser` plugin is `enabledByDefault: true`, `extensions/browser/openclaw.plugin.json`); base+9 … base+110 = browser CDP range. Docs advise ≥120 ports between gateways. See broken assumption B1.
  - Lock/singleton: one Gateway per state dir (process-owner lock keyed by the state DB path) + exclusive TCP bind; `OPENCLAW_ALLOW_MULTI_GATEWAY=1` "permits multiple config/runtime instances, not shared mutable state" (`docs:gateway/gateway-lock`). Note: the string `OPENCLAW_ALLOW_MULTI_GATEWAY` appears only in docs and tests in this commit, not as a literal in `src/` — whether it is needed for gateways of *different Windows users* on one host is **UNVERIFIED (lab L1)**.
- Auth modes; forcing token auth on loopback:
  - `gateway.auth.mode`: `none` | `token` | `password` | `trusted-proxy`. Token from `gateway.auth.token` or `OPENCLAW_GATEWAY_TOKEN` / `--token`. If both token and password are configured, `mode` must be set explicitly (`docs:gateway/config-gateway`, `docs:cli/gateway/running`).
  - To force token auth on loopback: `gateway: { bind: "loopback", auth: { mode: "token" } }` + token via env. `mode: "none"` is "explicit no-auth mode … only for trusted local loopback setups" — never use. `trusted-proxy` "expects a non-loopback proxy source"; same-host loopback trusted-proxy headers are not eligible (`docs:gateway/config-gateway`, `docs:gateway/pairing`).
  - **`gateway.auth.rateLimit.exemptLoopback` defaults to `true`** (failed-auth limiter skips localhost). On a shared RDS host every user is "localhost" → set **`exemptLoopback: false`** (`docs:gateway/config-gateway`).
  - Shared-secret (token/password) callers are full trusted operators: HTTP bearer restores scopes `operator.admin, operator.approvals, operator.pairing, operator.read, operator.talk.secrets, operator.write` (`docs:gateway/tools-invoke-http-api`).
  - Device pairing: WS clients normally include an Ed25519 device identity and sign the `connect.challenge` nonce; "Pairing auto-approval is centered on direct local loopback connects"; `gateway.nodes.pairing.autoApproveLocal` (default `true`) silently approves first-time pairing from trusted local connections; scope upgrades additionally need local-grade credentials (shared token). "Remote, trusted-CIDR, **browser**, and proxy connections do not gain local approval" (`docs:gateway/protocol/auth`, `docs:gateway/pairing`, `docs:gateway/config-gateway`).
  - Browser-origin WS connections are checked against `gateway.controlUi.allowedOrigins` / private-same-origin / local-loopback origin rules (`src/gateway/origin-check.ts` `checkBrowserOrigin`). A Tauri WebView origin (`http(s)://tauri.localhost`) is not obviously in any accepted class — **UNVERIFIED**; prefer connecting from Desk's Rust side (no `Origin` header).
- Client protocol (WS/HTTP) Desk will use:
  - Transport: WebSocket at the gateway root, `ws://127.0.0.1:<port>` (default URL `ws://127.0.0.1:18789`, `docs:gateway/gateway-lock`), text frames of JSON; first frame must be `connect`; pre-auth frames ≤64 KiB (`docs:gateway/protocol/transport`).
  - Frames (`packages/gateway-protocol/src/schema/frames.ts`): request `{ type:"req", id, method, params? }`; response `{ type:"res", id, ok, payload?, error? }`; event `{ type:"event", event, payload?, seq? }`.
  - Handshake (`docs:gateway/protocol/handshake`): server sends event `connect.challenge` `{ nonce, ts }` → client sends `req` `connect` with `{ minProtocol: 4, maxProtocol: 4, client: { id, version, platform, mode }, role: "operator", scopes: ["operator.read","operator.write","operator.approvals"], caps: [...], auth: { token }, device: { id, publicKey, signature, signedAt: <challenge ts>, nonce } }` → `res` payload `{ type: "hello-ok", protocol: 4, server, features, snapshot, auth: { role, scopes, deviceToken? }, policy: { maxPayload, maxBufferedBytes, tickIntervalMs, attachments } }`. Wire protocol version is **4**; operator clients must use exactly 4 (`docs:gateway/clients`).
  - `client.id` is a **closed enum** (`GatewayClientIdSchema = Type.Enum(GATEWAY_CLIENT_IDS)`, `packages/gateway-protocol/src/schema/primitives.ts`): `webchat-ui`, `openclaw-control-ui`, `openclaw-tui`, `webchat`, `cli`, `gateway-client`, `openclaw-macos`, `openclaw-linux`, … ; `client.mode` enum: `webchat|cli|ui|backend|node|worker|probe|test` (`packages/gateway-protocol/src/client-info.ts`). Desk cannot invent its own id. Which id/mode Desk should use is **UNVERIFIED** (candidate: `gateway-client` + `backend`, or `webchat` + `webchat`).
  - Device signature payload v3 = `buildDeviceAuthPayloadV3` in `packages/gateway-client/src/device-auth.ts` (`docs:gateway/protocol/auth`). Reference implementation: npm `@openclaw/gateway-client` (Node entry + `@openclaw/gateway-client/browser`) and `@openclaw/gateway-protocol`, both at 2026.11.6 on npm (`docs:gateway/clients` still says "verified stable 2026.8.1").
  - Send a chat message: `req` method **`chat.send`**, params (`ChatSendParamsSchema`, `packages/gateway-protocol/src/schema/logs-chat.ts`): required `sessionKey` (e.g. `"agent:main:main"`), `message: string`, `idempotencyKey: string`; optional `agentId`, `attachments`, `thinking`, `queueMode` (`steer|followup|collect|interrupt`), `deliver`, `timeoutMs`, `originatingChannel`, … Ack payload `{ runId, status: "started", … }` (`src/gateway/server-methods/chat-send-goal-ack.ts`).
  - Streamed output: `event` **`chat`** with payload union `ChatEventSchema` = `status` (`phase`), `delta` (`deltaText`, `replace?`, `usage?`), `final` (`message?`, `usage?`, `stopReason?`), `aborted`, `error` (`errorMessage`, `errorKind`); all carry `runId, sessionKey, seq` (`logs-chat.ts`). Tool events arrive as `agent` events only if the client advertises cap `tool-events` (`docs:gateway/clients`).
  - Other methods Desk needs: `chat.abort { sessionKey, runId? }`, `sessions.abort`, `chat.history`, `sessions.subscribe`, `sessions.usage`, `usage.cost`, `exec.approval.list/resolve`, `plugin.approval.list/resolve`, `approval.resolve` (`docs:gateway/protocol/rpc-session-control`, `docs:gateway/protocol/rpc-devices-nodes-and-approvals`, `docs:gateway/embedding`).
  - Readiness: wait for `connect.challenge`, then `hello-ok`; a `connect` during startup returns retryable `UNAVAILABLE` `details.reason: "startup-sidecars"` + `retryAfterMs`, close code 1013 (`docs:gateway/embedding`). Before orderly close the gateway emits event `shutdown { reason, restartExpectedMs? }`, then close 1012.
  - HTTP (unauthenticated probes): `GET /health` `/healthz` (live), `/startup` `/startupz`, `/ready` `/readyz` (`docs:gateway/health` "HTTP checks"). Authenticated HTTP uses `Authorization: Bearer <token>` (e.g. `POST /tools/invoke`, always enabled) (`docs:gateway/tools-invoke-http-api`). OpenAI-compatible `/v1/*` endpoints are off by default.
- Disabling or protecting the Control UI:
  - `gateway.controlUi.enabled: false` (default `true`; source `?? true` in `src/gateway/server-runtime-config.ts`) (`docs:gateway/config-gateway`).
  - Also disable the operator terminal: **`gateway.terminal.enabled` defaults to `true`** (`src/gateway/terminal/enabled.ts`: `config?.gateway?.terminal?.enabled !== false`) and gives admin-scope clients a host PTY → set `false`.
  - `gateway.uploads.enabled` (default true) can reject client uploads (`docs:gateway/config-gateway`).
- Start in the foreground: `openclaw gateway` ≡ `openclaw gateway run`, flags `--port <n>`, `--bind <mode>`, `--auth <none|token|password|trusted-proxy>`, `--token <t>` (defaults to `OPENCLAW_GATEWAY_TOKEN`), `--password`, `--password-file`, `--allow-unconfigured`, `--force`, `--verbose`, `--ws-log`, `--ambient-channels` (off by default: channels are only started from explicit `channels.<id>` config) (`docs:cli/gateway/running`). Graceful stop: SIGTERM/SIGINT (process title `openclaw-gateway`).

## 4. Plugin SDK
- Manifest format, entry point, packaging:
  - Manifest file **`openclaw.plugin.json`** in the plugin root, parsed as JSON5; **required fields: `id` (string) and `configSchema` (inline JSON Schema object)**; read before any plugin code runs; missing/invalid manifest blocks config validation (`docs:plugins/manifest` "Top-level field reference"). Useful optional fields: `name`, `description`, `activation: { onStartup: true }` ("Omitting `onStartup` no longer startup-loads the plugin implicitly", `docs:plugins/manifest/capabilities`), `channels: ["<channel-id>"]`, `channelConfigs`, `contracts` (`tools`, `agentToolResultMiddleware`, `trustedToolPolicies`, …), `requiresPlugins`.
  - `package.json`: `"type": "module"` and an `openclaw` block: `extensions: ["./dist/index.js"]` (entrypoints, must stay inside the package dir), optional `runtimeExtensions`, `setupEntry` (channels), `channel: { id, label, blurb, … }`, `install.minHostVersion` (enforced at install and at manifest registry loading for non-bundled plugins), `compat.pluginApi` (enforced at package install) (`docs:plugins/manifest/package-json`; example in `docs:plugins/building-plugins`).
  - Entry shape: default export of **`definePluginEntry({ id, name, description, configSchema?, reload?, register(api) })`** from **`openclaw/plugin-sdk/plugin-entry`** (`src/plugin-sdk/plugin-entry.ts`). `id` must equal the manifest id. Channel plugins use **`defineChannelPluginEntry({ id, name, description, plugin, setRuntime?, registerCliMetadata?, registerFull? })`** from **`openclaw/plugin-sdk/channel-core`** (re-exported from `src/plugin-sdk/core.ts`). `register(api)` must be synchronous (`docs:plugins/hooks/reference`).
  - `api` (`OpenClawPluginApi`, `src/plugins/plugin-api.types.ts`): `id`, `config`, `pluginConfig`, `runtime`, `logger`, `on(hook, handler, opts?)`, `registerTool`, `registerService`, `registerChannel`, `registerGatewayMethod`, `registerHttpRoute`, `registerCommand`, `registerAgentToolResultMiddleware`, `registerTrustedToolPolicy`, `registerInteractiveHandler`, `runContext.{set,get,clear}RunContext`, `agent.events.{registerAgentEventSubscription,emitAgentEvent}`, `session.{state,workflow,controls}`, `lifecycle.registerRuntimeLifecycle`, `resolvePath`.
  - SDK import paths are `openclaw/plugin-sdk/<subpath>` (package `exports` of `openclaw`). Shipped `.d.ts` in the npm tarball were checked via unpkg for `plugin-entry`, `core`, `channel-core`, `channel-contract`, `channel-inbound`, `channel-outbound`, `routing`, `gateway-runtime`, `runtime-store`, `interactive-runtime`, `hook-runtime`, `agent-harness-runtime`, `status-helpers` (present). `openclaw/plugin-sdk/types` ships **no** `.d.ts` (root `package.json` `files` has `!dist/plugin-sdk/types.d.ts`), so hook event types (`PluginHookBeforeToolCallEvent`, …) are not importable by name from npm — rely on inference through `api.on(...)`. Build plugins against devDependency `openclaw@2026.11.6` for types. `@openclaw/plugin-sdk` is not published on npm.
  - At runtime the host supplies `openclaw/plugin-sdk/*` aliases to native plugins ("prepares SDK aliases before evaluation", `docs:plugins/architecture-internals/load-pipeline`), so a plugin dir outside the OpenClaw package does not need its own `openclaw` dependency — **lab-verify for a `plugins.load.paths` dir under Program Files**.

## 5. Hooks for guard
Full typed hook list at 2026.11.6 (`PluginHookHandlerMap` / `PLUGIN_HOOK_METADATA`, `src/plugins/hook-types.ts`; `docs:plugins/hooks/reference` "Hook catalog"): `before_model_resolve`, `agent_turn_prepare`, `before_prompt_build`, `before_agent_run`, `before_agent_reply`, `before_agent_finalize`, `agent_end`, `heartbeat_prompt_contribution`, `model_call_started`, `model_call_ended`, `llm_input`, `llm_output`, `before_tool_call`, `after_tool_call`, `resolve_exec_env`, `tool_result_persist`, `before_message_write`, `before_channel_ingress`, `inbound_claim`, `channel_pairing_requested`, `message_received`, `message_sending`, `reply_payload_sending`, `message_sent`, `before_dispatch`, `reply_dispatch`, `session_start`, `session_end`, `before_compaction`, `after_compaction`, `before_reset`, `subagent_spawned`, `subagent_progress`, `subagent_ended`, `subagent_delivery_target`, `gateway_start`, `gateway_stop`, `cron_reconciled`, `cron_changed`, `before_install`, `skill_changed`. Register with `api.on(name, handler, { priority?, timeoutMs?, matcher?, eligibleTriggers? })`; handler `(event, ctx)`.
- Before/after turn hooks; can they reject a turn?
  - **`before_agent_run`** (Gate; conversation access required): event `{ prompt, images?, messages, systemPrompt?, accountId?, channelId?, senderId?, senderIsOwner? }` (`src/plugins/hook-before-agent-start.types.ts`); return `{ outcome: "pass" }` or `{ outcome: "block", reason, message?, category?, metadata? }` or void (`src/plugins/hook-decision-types.ts`). User-facing text becomes `"Your message could not be sent: <message>"`. Default timeout 15 s; **thrown error or timeout blocks the run** (fail-closed) (`docs:plugins/hooks/reference`). Implemented by the embedded and CLI runners and Gateway worker admission; not a Codex/Copilot input gate (`docs:plugins/hooks`). → use for lock/licence/channel policy.
  - `before_agent_reply` (Claim): `{ cleanedBody }` → `{ handled: true, reply?: ReplyPayload, reason? }` short-circuits the model turn (synthetic reply or silence).
  - `before_dispatch` (Claim): `{ content, body?, channel?, sessionKey?, senderId?, … }` → `{ handled, text? }`.
  - `before_agent_finalize` (Modify): can request another model pass (`action: "revise"`), cannot veto.
  - `agent_end` (Observe): `{ runId?, messages, success, error?, durationMs? }`.
- Before/after tool call hooks; can they block, modify, or replace with a result?
  - **`before_tool_call`** (Modify/Gate; no conversation-access grant needed): event `{ toolName, params, toolKind?, toolInputKind?, runId?, toolCallId?, derivedPaths? }`; result `{ params?, block?, blockReason?, requireApproval?: { title, description, severity?, timeoutMs?, timeoutReason?, allowedDecisions?, onResolution? } }` (`src/plugins/hook-types.ts`, `src/plugins/hook-before-tool-call-result.ts`). `block: true` is terminal; last returned `params` wins; first `requireApproval` wins and pauses the run (plugin approval, default 120 s, max 600 s — `docs:plugins/plugin-permission-requests`). Default timeout 15 s, error/timeout **blocks the call**. `matcher` = list of tool ids (`exec`, `read`, …).
  - It **cannot return a synthetic successful result**; a block returns a blocked-tool result to the model. "Queued for review" must therefore be a block with an explanatory `blockReason` (or a guard-owned tool the agent calls instead).
  - `api.registerTrustedToolPolicy(...)` runs before ordinary `before_tool_call` hooks; installed plugins must declare ids in `contracts.trustedToolPolicies` (`docs:plugins/hooks/tool-policy`).
  - **`after_tool_call`** (Observe): event `{ toolName, params, runId?, toolCallId?, result?, error?, durationMs? }`; "Handlers run concurrently and their return values are ignored … cannot change what already happened … Do not use this hook to enforce policy" (`docs:plugins/hooks/tool-policy`). **It cannot change the result or stop the turn.**
  - **`api.registerAgentToolResultMiddleware(handler, { runtimes?, matcher? })`**: rewrites a tool result *before it is fed back to the model*; event `{ toolCallId, toolName, args, cwd?, isError?, result: { content, details }, threadId?, turnId? }`, ctx `{ runtime, agentId?, sessionId?, sessionKey?, runId? }`, return `{ result }` or void (`src/plugins/agent-tool-result-middleware-types.ts`; `docs:plugins/sdk-overview/host-hooks`). Requires manifest `contracts.agentToolResultMiddleware`.
  - `tool_result_persist` / `before_message_write` are synchronous transcript-persistence rewrites, "not a tool-execution veto".
  - There is **no plugin API to abort a run** in `OpenClawPluginApi` / `PluginRuntime` (`src/plugins/plugin-api.types.ts`, `src/plugins/runtime/types-core.ts` reviewed); the nearest are `api.session.workflow.steerActiveRun({ sessionKey, text })` and, from the client side, `chat.abort`.
- What a tool failure looks like (errors for EACCES / Windows error 5):
  - Thrown tool errors become a result `{ content: [{ type: "text", text: <error message> }], details: {} }` with `isError: true` (`packages/agent-core/src/tool-call-outcome.ts` `createToolExecutionErrorResult`/`createErrorToolResult`; `packages/agent-core/src/agent-loop-tool-execution.ts`). The errno `code` is **not** part of the model-visible result; only the message text.
  - `read` tool: `stat` via `node:fs/promises`, then `readRegularFile` from `@openclaw/fs-safe/advanced` (in a worker); non-ENOENT/EISDIR errors are re-thrown via `toErrorObject` (`src/agents/sessions/tools/read.ts` `normalizeReadError`, `read-file.ts`). The exact message text from fs-safe for a Windows access-denied is **UNVERIFIED** (package not in the repo; lab).
  - Node/libuv maps Win32 `ERROR_ACCESS_DENIED` (5) and `ERROR_PRIVILEGE_NOT_HELD` → **`EPERM`**; `ERROR_CANT_ACCESS_FILE`, `ERROR_ELEVATION_REQUIRED`, `WSAEACCES` → `EACCES`; `ERROR_SHARING_VIOLATION`/`ERROR_LOCK_VIOLATION` → `EBUSY` (libuv `src/win/error.c`, v1.x branch, fetched 2026-11-22). So on Windows expect mostly `EPERM: operation not permitted, open '…'`. Guard should match `EPERM|EACCES` (and probably `EBUSY` separately).
  - `exec` (PowerShell) access-denied is command output (stderr text + exit code), not a thrown tool error; its `result` shape for after-hooks is tracked upstream in issue #102961 (`docs:plugins/hooks/tool-policy`). **UNVERIFIED (lab).**
  - `apply_patch` cannot write outside the workspace by default: `tools.exec.applyPatch.workspaceOnly: true` (default); `tools.fs.workspaceOnly` is optional/false (`docs:gateway/security/tool-permissions`).
- Per-channel context available to hooks:
  - Tool hooks: `ctx = { agentId?, sessionKey?, sessionId?, runId?, toolName, toolCallId?, channelId?, requester?: { channel?, accountId?, senderId?, senderIsOwner?, roleIds? }, trigger? ("user"|"cron"|"memory"…), abortSignal?, getSessionExtension? }` (`src/plugins/hook-tool-context.types.ts`). "Missing fields are unproven, not false assurances."

  - Plugin approvals (`before_tool_call` → `requireApproval`) block the run while waiting; `timeoutMs` default 120 000, capped at 600 000; timeout ⇒ call blocked (`docs:plugins/plugin-permission-requests`).
- Lobster approval API:
  - Separate npm plugin `@openclaw/lobster` (2026.11.6), optional tool `lobster`, enable with `tools.alsoAllow: ["lobster"]`; disabled in sandboxed contexts; runs typed pipelines in-process (`docs:tools/lobster`).
  - Approval = tool-call protocol: `{ action: "run", pipeline, timeoutMs }` → `{ status: "needs_approval", requiresApproval: { prompt, items, resumeToken, approvalId } }`; resume with `{ action: "resume", token | approvalId, approve: true|false }` (or `responseJson` / `cancel: true` for input). "The plugin does not list pending checkpoints"; possession of the token permits resume by any caller allowed to use the tool — i.e. **the agent itself can approve** (`docs:tools/lobster`).
  - Conclusion for ADR: Lobster gives no human-only, durable, listable review queue; plugin approvals are synchronous (≤10 min). The guard should own the review queue (see "Known gaps", ADR proposal).
